The board is a list of pieces, never a bitmap: {id, row, col, len, orient} and nothing else. The 6×6 occupancy grid you can see is derived — rebuilt from that list on every query — so the drawing and the rules can never disagree. A move is a delta along the piece's own axis, clamped to the run of empty cells found by walking outward in both directions, which is why nothing ever overlaps and nothing ever leaves the board. Flatten the 36 cells into one canonical string and the puzzle becomes a graph: breadth-first search sweeps it layer by layer, so the first time it touches a winning position it has found the provably shortest escape. That single search powers the hint, the auto-solver, the "optimal" number, and the generator — which refuses to hand you a jam it has not already solved.

🔨 Build it yourself

    
Rush Hour is the friendliest introduction to state-space search there is, because the puzzle is small enough to hold in your head and the search is small enough to run on every single move. The whole game is a list of {row, col, len, orient} records, one derived occupancy grid, and a function that counts empty cells in front of and behind a piece. Once you can turn a board into a string, you get breadth-first search — and with it a provably optimal solver, an honest hint, an auto-play, and a puzzle generator that verifies its own output. Nine blocks, in order, from an empty file.

    1
    The piece list, and the occupancy grid you never store
    
        
    A vehicle is four numbers and a letter: where its top-left cell is, how long it is, and which way it points. That is the entire board — typically ten to thirteen little records. The 6×6 grid of "who is standing here" is derived, rebuilt from the list whenever a rule needs it, which is the single most important decision in the file: there is only one copy of the truth, so the picture and the rules can never drift apart.
    
        
    const N = 6, EXIT_ROW = 2;                 // the red car always escapes along row index 2

// a piece is just: { id, row, col, len, orient }   orient = "H" or "V"
function cellsOf(p){
  const out = [];
  for (let k = 0; k < p.len; k++)
    out.push(p.orient === "H" ? [p.row, p.col + k] : [p.row + k, p.col]);
  return out;
}

// derived, never stored: cell -> index of the piece sitting there, or -1
function occupancy(pieces){
  const g = new Int8Array(N * N).fill(-1);
  for (let i = 0; i < pieces.length; i++)
    for (const [r, c] of cellsOf(pieces[i])) g[r * N + c] = i;
  return g;
}

    The slide range — how far can this vehicle actually go
    
        
    Every rule in Rush Hour collapses into one function. A piece is axis-locked, so it has exactly one degree of freedom, and the only question is how far it can travel each way. Walk outward from its nose until you hit a wall or another vehicle, then walk outward from its tail the same way. The two counts are a closed interval [min, max] of legal deltas — and because you never step past an occupied cell, a piece can never tunnel through traffic.
    
        
    function slideRange(pieces, i, grid){
  const g = grid || occupancy(pieces), p = pieces[i];
  let back = 0, fwd = 0;
  if (p.orient === "H"){
    let c = p.col - 1;         while (c >= 0 && g[p.row*N + c] === -1){ back--; c--; }
    c = p.col + p.len;         while (c <  N && g[p.row*N + c] === -1){ fwd++;  c++; }
  } else {
    let r = p.row - 1;         while (r >= 0 && g[r*N + p.col] === -1){ back--; r--; }
    r = p.row + p.len;         while (r <  N && g[r*N + p.col] === -1){ fwd++;  r++; }
  }
  return { min: back, max: fwd };     // e.g. { min: -2, max: 1 }
}

    Every legal move, and applying one without mutating anything
    
        
    The move list is just the ranges of all pieces flattened, skipping the do-nothing delta of zero. Note that a slide of any distance counts as one move — that is the standard Rush Hour metric, and it is what makes "optimal 8" mean something. Applying a move copies the list and adds the delta to one field: column for a horizontal piece, row for a vertical one. Copying instead of mutating is what lets the search hold thousands of boards at once without them corrupting each other.
    
        
    function legalMoves(pieces){
  const g = occupancy(pieces), out = [];
  for (let i = 0; i < pieces.length; i++){
    const { min, max } = slideRange(pieces, i, g);
    for (let d = min; d <= max; d++) if (d !== 0) out.push({ i, d });
  }
  return out;
}

function applyMove(pieces, i, d){
  const next = pieces.map(p => ({ ...p }));   // immutable: the search depends on it
  if (next[i].orient === "H") next[i].col += d; else next[i].row += d;
  return next;
}

const isWin = pieces => { const red = pieces.find(p => p.id === 0);
  return red.row === EXIT_ROW && red.col + red.len === N; };

    Squashing a board into one canonical string
    
        
    To search, you need to recognise a position you have already seen — and the piece list is a terrible identity, because the same picture written in a different array order would look like a new board. So paint the 36 cells instead, labelling each one by what kind of thing occupies it: the red car, a car or a truck, horizontal or vertical. Two identical trucks are genuinely interchangeable, so this key deliberately merges them, which collapses whole families of duplicate states into one.
    
        
    function key(pieces){
  const s = new Array(N * N).fill(".");
  for (const p of pieces){
    const ch = p.id === 0 ? "X"
             : p.orient === "H" ? (p.len === 2 ? "h" : "H")
                                : (p.len === 2 ? "v" : "V");
    for (const [r, c] of cellsOf(p)) s[r * N + c] = ch;
  }
  return s.join("");        // 36 chars, independent of the order of the array
}
// "..v..H" + "..v..H" + "XX...H" + ... -> one string, one Set entry

    Breadth-first search — the shortest escape, provably
    
        
    Positions are nodes, moves are edges, and BFS explores that graph in rings: everything one move away, then everything two moves away, and so on. Because a ring is finished before the next one starts, the first winning board it reaches is reached in the fewest possible moves — that is the whole guarantee, and it is why a plain queue beats any amount of clever guessing here. Keep a parent pointer beside every node and walk it backwards to recover the actual move list.
    
        
    function solve(pieces, cap = 400000){
  const start = pieces.map(p => ({ ...p }));
  const q = [start], parent = [-1], moveOf = [null];
  const seen = new Set([key(start)]);
  let head = 0, explored = 0;
  while (head < q.length && explored < cap){
    const cur = q[head], idx = head++; explored++;
    if (isWin(cur)){                             // first hit = shortest, by construction
      const moves = [];
      for (let k = idx; parent[k] !== -1; k = parent[k]) moves.push(moveOf[k]);
      return { solvable: true, moves: moves.reverse(), states: explored };
    }
    for (const m of legalMoves(cur)){
      const nx = applyMove(cur, m.i, m.d), kk = key(nx);
      if (seen.has(kk)) continue;                // already reached, and never slower
      seen.add(kk); q.push(nx); parent.push(idx); moveOf.push(m);
    }
  }
  return { solvable: false, moves: null, states: explored };
}

    Hint and auto-solve are the same search, twice
    
        
    Because the solver is fast enough to run on every move, there is no reason to store a plan. A hint is simply "solve from where we are now, show move zero" — which stays correct no matter how badly the player has wandered off the original path. Auto-solve is the same call with a timer draining the list. Re-solving after each move also gives you the honest "moves left at best" counter, and the little humiliation of watching it go up when you make a bad move.
    
        
    function hint(pieces){
  const res = solve(pieces);
  return res.solvable && res.moves.length ? res.moves[0] : null;   // recomputed, never cached
}

function autoSolve(pieces, step){          // step(move) applies it and redraws
  const res = solve(pieces);
  if (!res.solvable) return;
  const seq = res.moves.slice(); let k = 0;
  const t = setInterval(() => { if (k >= seq.length){ clearInterval(t); return; }
                                step(seq[k++]); }, 430);
}
// scoreboard: optimal from the START vs the player's count -> "optimal 8 · you 14"

    Generate-then-verify: never ship a jam you have not solved
    
        
    Random vehicles almost never make a good puzzle — most scatters are trivially open, and plenty are impossible. So do not be clever: scatter, then ask the solver, and throw away anything it cannot solve or solves too quickly. One rule saves most of the failures — a horizontal vehicle parked on the exit row can never leave that row, so if one sits to the right of the red car the jam is unwinnable by construction; forbid it while placing.
    
        
    function generate(rng, opts = {}){
  const { minMoves = 10, maxMoves = 60, want = 11, tries = 4000 } = opts;
  const ri = n => Math.floor(rng() * n);
  for (let t = 0; t < tries; t++){
    const pieces = [{ id:0, row:EXIT_ROW, col: ri(3), len:2, orient:"H" }];
    for (let guard = 0; pieces.length < want && guard < 300; guard++){
      const orient = rng() < 0.5 ? "H" : "V", len = rng() < 0.68 ? 2 : 3;
      const cand = { id: pieces.length, len, orient,
                     row: ri(orient === "V" ? N - len + 1 : N),
                     col: ri(orient === "H" ? N - len + 1 : N) };
      if (orient === "H" && cand.row === EXIT_ROW) continue;   // would be a permanent wall
      if (!fits(pieces, cand)) continue;
      pieces.push(cand);
    }
    const res = solve(pieces, 200000);                          // VERIFY, do not hope
    if (res.solvable && res.moves.length >= minMoves && res.moves.length <= maxMoves)
      return { pieces, optimal: res.moves.length, attempts: t + 1 };
  }
  return null;
}

    Pointer drag that snaps to whole cells and refuses to cheat
    
        
    Dragging feels analogue but the model is not, so convert immediately: divide the pointer's travel along the piece's axis by the cell size, round to the nearest integer, and clamp that integer into the slide range you already computed at grab time. The clamp is the important half — it means the piece visibly refuses to pass through a car even while your finger keeps going. Set touch-action:none on the canvas or the browser will steal the gesture and scroll the page instead.
    
        
    canvas.addEventListener("pointerdown", e => {
  const p = toCanvas(e), cell = cellAt(p.x, p.y); if (!cell) return;
  const i = occupancy(pieces)[cell.r * N + cell.c];
  if (i < 0) return;                                  // empty cell: nothing grabbed
  canvas.setPointerCapture(e.pointerId);
  drag = { i, x: p.x, y: p.y, range: slideRange(pieces, i), off: 0 };
});
canvas.addEventListener("pointermove", e => {
  if (!drag) return;
  const p = toCanvas(e), pc = pieces[drag.i];
  const raw = pc.orient === "H" ? (p.x - drag.x) / CELL : (p.y - drag.y) / CELL;
  const d = Math.max(drag.range.min, Math.min(drag.range.max, Math.round(raw)));
  if (d !== drag.off){ drag.off = d; render(); }       // snapped AND clamped
});
canvas.addEventListener("pointerup", () => {
  if (drag && drag.off !== 0) doMove(drag.i, drag.off);
  drag = null; render();
});

    Undo, and the move that ties it all together
    
        
    Because applyMove never mutates, undo is embarrassingly cheap: push a snapshot before the move, pop it afterwards. No inverse move to derive, no edge cases when the auto-solver is halfway through a run. Every path into the game — a drag, a tap on an empty cell in the lane, the arrow pad, the keyboard, the solver's timer — funnels into the same doMove, so there is exactly one place where the move counter, the win test and the re-solve happen.
    
        
    const history = [];

function doMove(i, d){
  if (over || !d) return;
  history.push(pieces.map(p => ({ ...p })));      // snapshot BEFORE
  pieces = applyMove(pieces, i, d);
  moves++; hint = null; sel = i;
  if (isWin(pieces)) return finish();
  const res = solve(pieces);                     // honest "left (best)" + states counter
  remaining = res.moves.length; lastStates = res.states;
  render();
}

function undo(){
  const prev = history.pop(); if (!prev) return;
  pieces = prev; moves = Math.max(0, moves - 1); over = false;
  render();
}
