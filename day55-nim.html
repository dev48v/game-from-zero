🔨 Build it yourself

    
Nim has almost no code and almost all theory. The state is a list of heap sizes; a move subtracts from one of them; the game ends when they are all zero. What makes it worth building is the opponent: a provably perfect AI in about ten lines, resting on one 1901 theorem — a position is lost for the player to move exactly when the XOR of the heap sizes (the "nim-sum") is zero. Below, the whole engine in seven short blocks: state, a move, the nim-sum, the theorem, the winning move that always zeroes it, the misère endgame twist, and the wiring. Copy each block in order.

    
    

      
  1. 
        
    1
    The whole game is a list of heap sizes
    
        
    There is no board and there are no piece objects — the entire position is an array of integers, one per heap. Alongside it you only need to know whose turn it is, whether you are playing misère (last object loses instead of wins), and the little move the player is currently building with clicks. A second copy of the starting sizes is kept just so the display can draw the already-taken objects as faded "ghosts"; it plays no part in the rules.
    
        
    let heaps    = [3, 4, 5];           // sizes of each heap — the whole position
let original = [3, 4, 5];           // starting sizes, only for drawing ghosts
let turn     = "you";               // "you" | "cpu"
let misere   = false;               // false = take the LAST object to WIN
let phase    = "play";              // "play" | "over"
let winner   = null;
let sel      = { heap:-1, take:0 }; // the move you are building by clicking

  2. 
        
    2
    A move: take any number from one heap
    
        
    The single rule of Nim is that on your turn you remove at least one object, all from the same heap — one, several, or the whole heap, your choice. So the move itself is one subtraction on one array slot. The game is over the instant every heap is empty; the player who made that final move took the last object, which wins in normal play and loses in misère.
    
        
    function applyMove(heaps, heap, take){
  heaps[heap] -= take;              // remove `take` objects from one heap — that's it
}
function legal(heaps, heap, take){
  return take >= 1 && take <= heaps[heap];   // at least one, at most the whole heap
}
function isOver(heaps){
  return heaps.every(h => h === 0);          // all heaps empty = game over
}
    
      
    3. 

      
  3. 
        
    3
    The nim-sum — XOR every heap size
    
        
    Here is the one magic number the whole game turns on. Fold the heap sizes together with bitwise XOR and you get the nim-sum. XOR is binary addition with the carries thrown away, so each bit of the nim-sum is 1 exactly when an odd number of heaps have that bit set. A nim-sum of zero therefore means every binary column is balanced — an even number of heaps contribute each power of two.
    
        
    function nimSum(heaps){
  return heaps.reduce((a, h) => a ^ h, 0);  // XOR fold — the "nim-sum"
}

//   heaps [3, 4, 5]
//     3 = 0 1 1
//     4 = 1 0 0
//     5 = 1 0 1
//   xor = 0 1 0   → nim-sum 2   (bit columns: two 1s, two 4s → balanced;
//                                 one 2 → the odd one out, so bit set)

  4. 
        
    4
    Bouton's theorem — nim-sum zero is a dead position
    
        
    In 1901 Charles Bouton proved the entire game with a single statement: a position is a loss for the player about to move if and only if its nim-sum is zero. The reasoning is a two-line invariant. From a balanced position (sum zero) any move you make touches exactly one heap, flips some bits, and so must unbalance at least one column — you always hand back a non-zero sum. From an unbalanced position (sum non-zero) there is always a move that rebalances it to zero. So a player who keeps handing over zero can never be forced off it, and the last balanced position — every heap empty — is the loss.
    
        
    function isLosingForMover(heaps){
  return nimSum(heaps) === 0;       // sum 0 → mover loses under perfect play
}
//   sum === 0  → any move UNbalances a column → opponent gets a non-zero sum
//   sum !== 0  → you can always rebalance to 0 → opponent is stuck again
//   [0,0,0] has sum 0 and no move → the player to "move" has already lost
    
      
    5. 

      
  5. 
        
    5
    The winning move always zeroes the nim-sum
    
        
    Turning the theorem into a move is three lines. When the sum x is non-zero, look at each heap's target size h ^ x. Because x has a highest set bit, the heap that also has that bit set will see it cleared by the XOR, making h ^ x < h — so you can legally shrink that heap to h ^ x. After the move the new nim-sum is x ^ h ^ (h ^ x) = 0: you have rebalanced every column and handed your opponent a dead position. There is always at least one such heap whenever x ≠ 0.
    
        
    function winningMove(heaps){
  const x = nimSum(heaps);
  if (x === 0) return null;                    // balanced → no winning move exists
  for (let i = 0; i < heaps.length; i++){
    const target = heaps[i] ^ x;               // where this heap must land
    if (target < heaps[i])                     // can only ever SHRINK a heap
      return { heap:i, take: heaps[i] - target };
  }
}
// proof the new sum is 0:   x ^ heaps[i] ^ (heaps[i] ^ x)  ==  0

  6. 
        
    6
    Misère — the endgame flips, and only then
    
        
    If taking the last object loses, the surprise is that you play the exact same nim-sum strategy almost the whole way — it only diverges at the very end. Watch for the moment when at most one heap has more than one object. Before that, play normal Nim. At that endgame you switch goals: leave your opponent an odd number of single-object heaps, because a player facing an odd count of lone objects is forced to take the last one. So if one fat heap remains, reduce it to 0 or 1 to make the count of ones odd; if only ones are left, you are simply counting parity.
    
        
    function bestMove(heaps, misere){
  const big  = heaps.filter(h => h > 1).length;   // heaps with 2+ objects
  const ones = heaps.filter(h => h === 1).length; // single-object heaps
  if (misere && big <= 1){                         // the misère endgame — and ONLY here
    if (big === 1){                                // one fat heap left to shape
      const i = heaps.findIndex(h => h > 1);
      const target = ones % 2 === 0 ? 1 : 0;       // leave an ODD number of 1s
      return { heap:i, take: heaps[i] - target };
    }
    const i = heaps.findIndex(h => h === 1);       // only 1s remain: forced parity
    return { heap:i, take:1 };
  }
  return winningMove(heaps) || playOn(heaps);      // otherwise: normal nim-sum theory
}

  7. 
        
    7
    Playing on, and wiring the turns
    
        
    When the nim-sum is already zero the AI is, in theory, lost — there is no rebalancing move — so it just plays on: it takes one object from the largest heap and hopes you slip. That is exactly why a human who understands the trick can beat a "perfect" opponent: move first from a non-zero position, always hand back a zero, and the AI never gets a chance. The rest is turn-taking — apply the move, check for game over (the last mover wins in normal play, loses in misère), otherwise pass the turn.
    
        
    function playOn(heaps){                          // lost position → stall for a mistake
  let i = 0;
  for (let k = 1; k < heaps.length; k++) if (heaps[k] > heaps[i]) i = k;
  return { heap:i, take:1 };
}
function cpuTurn(){
  const m = bestMove(heaps, misere);            // perfect when a winning move exists
  applyMove(heaps, m.heap, m.take);
  if (isOver(heaps)) finish("cpu");             // "cpu" took the last object
  else               turn = "you";
}
function finish(mover){                          // who took the last object?
  phase = "over";
  winner = misere ? other(mover) : mover;       // misère: last mover LOSES
}
const other = p => p === "you" ? "cpu" : "you";
