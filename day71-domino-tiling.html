GAMEFROMZERO · DAY 71

🧮 Domino Tiling — a board with holes punched in it, and 2×1 tiles to cover whatever is left. Every engine in this series so far answers what is the best move. This one answers how many, and everything else is a by-product: a move is survivable when the number of ways to finish stays above zero, it is forced when that number does not change at all, and its odds of appearing in a random finish are its share of the count. So the engine is not a search and not a tablebase, it is an exact counter — a broken-profile dynamic program carrying a W-bit frontier across the cells in reading order, 2W states in place of 2W×H subsets, 256 instead of eighteen quintillion on an 8×8, which is the only reason a board with 12,988,816 tilings can be scored between two clicks. It is checked against brute force, against a bipartite matching that cannot count at all, against Kasteleyn's eigenvalue product, against the Aztec diamond's 2n(n+1)/2, and against a permanent, on every one of the 65,536 boards sixteen cells can be in. And then the two things that inverted. First: the colour argument — the most famous fact in this entire subject, the one that kills the mutilated chessboard in a sentence — found 0 of 4,461 fatal moves, and cannot ever find one, because a domino removes one square of each colour by construction, so the quantity it watches is the one quantity a move can never change. Second: the puzzle I set out to build, a board where every domino is forced and no local rule can see any of them, does not exist and cannot — 5,337 uniquely-tileable boards on load and 17,817 once the deep sweep runs, every one of them finished by a one-line rule with no arithmetic in it. Exact counting is worth exactly nothing on a puzzle with one answer, and worth 100% against 0% the moment there are two. Pure vanilla JS, one file, no build step.

The engine is a number, not a move

Cover a board with dominoes. Some cells are punched out; every remaining cell has to end up under exactly one half of one 2×1 tile. That is the entire rulebook, and it is the first game in this series whose engine does not choose anything.

Ask the question a player actually has: is this move safe? It has no local answer. Lay a domino in the middle of a wide open board and the board still looks wide open — every cell still has neighbours, the colour count is still even, nothing has visibly broken — and the puzzle can already be dead. The only honest test is to ask how many ways there are to finish from the position you would be in. If the answer is zero, the move was fatal. If the answer equals the number of ways to finish from where you are now, the move was free: every finish uses it, so playing it costs nothing.

Both of a player's questions are one question about a count. dead = count(after) is 0 · forced = count(after) equals count(now) · odds = count(after) / count(now). There is no evaluation function on this page and no search. There is a counter, and three comparisons.

Why the count cannot simply be enumerated

An 8×8 board has 12,988,816 tilings. A 10×10 has 258,584,046,368. A 12×14 has 43,242,613,716,069,407,953. Listing them is not slow, it is impossible, and it is impossible at board sizes that fit comfortably on a phone screen. Every one of those numbers on this page was produced without a single tiling ever being constructed.

The compression: a frontier, not a subset

The obvious state for “which cells are still uncovered” is a subset of the board: 264 of them on an 8×8, which is eighteen quintillion and the end of the conversation. The trick is to fix the order. Sweep the cells in reading order and keep a cursor. Everything behind the cursor is settled. Everything more than W cells ahead of it is untouched. The only thing in doubt is the W cells starting at the cursor — some of them are already covered by a domino that reached in from behind, and the rest are not.

state = a W-bit mask.  bit j = "the cell j steps ahead of the cursor is already covered"

at the cursor:
  bit 0 set   -> covered from behind; shift and step on
  a hole      -> nothing to cover;    shift and step on
  otherwise   -> this cell MUST be the left or top half of a domino:
                   place it right -> set bit 1        (the cell next door)
                   place it down  -> set bit W        (the cell below)
                 then shift the mask down by one and step on

2W states, not 2W×H. 256 instead of eighteen quintillion. The whole DP is two nested loops and four lines of body, it is exact, and it does not care where the holes are. That is the entire engine; everything else on this page is a consequence of it or a check on it.

Four solvers that agree, and one that cannot count

A compression is exactly the kind of thing that is silently wrong, so the DP is not trusted anywhere on this page. It is checked against:

  • Brute force — cover the first uncovered cell the two possible ways and recurse. No frontier, no mask. Run on all 65,536 boards of a 4×4 and all 1,048,576 of a 4×5 behind the button.
  • A bipartite matching — the grid graph is bipartite by colour, so Kuhn's algorithm answers tileable or not with no notion of “how many” anywhere inside it. It must agree with count > 0 on every board.
  • Kasteleyn and Temperley–Fisher, 1961 — an eigenvalue product for rectangles, which is analysis and not combinatorics. It is a floating-point formula, so it is compared by relative error rather than equality, and it lands within 1.2×10−14.
  • The Aztec diamond — a non-rectangular region with exactly 2n(n+1)/2 tilings. Punch the diamond out of a square and the DP returns 2, 8, 64, 1024, 32768, 2097152 for orders one to six.
  • A permanent — the verifier computes Ryser's inclusion–exclusion formula for the permanent of the biadjacency matrix, which is the number of perfect matchings by definition and shares nothing with any of the above.

The one thing everybody knows about dominoes, and what it is worth

Colour the board like a chessboard. Every domino covers one dark and one light square, so a board with unequal colour counts cannot be tiled. That is the mutilated chessboard argument, it is beautiful, it is one line, and it is the first thing anybody says about this subject.

Measured, over every board of sixteen cells: 12,870 of them have equal colour counts and only 5,700 can actually be tiled. The colour test is right 44.3% of the time on a 4×4 and 31.8% on a 4×5 — it gets worse as the board grows. Tighten it to “every connected component is balanced” and it climbs to 97.6% and 94.3%, still not exact. Only the matching is exact, because the real characterisation is Hall's condition and nothing cheaper.

🔴 And inside the game the colour argument is worth precisely zero. Across 4,461 fatal moves measured over three board configurations, the number the colour test watches detected none of them — and it never can, because a domino removes one square of each colour by construction. Every legal move preserves the balance exactly. The most famous invariant in the subject is constant along every edge of the game graph, which makes it perfectly true and completely useless to a player.

Gomory's theorem, and the exact moment it stops helping

Ralph Gomory, 1973: take a rectangle with an even number of cells, remove one dark square and one light square anywhere at all, and what is left can always be tiled. The proof is a picture — a rectangle with an even cell count has a Hamiltonian cycle through every cell, and two removals of opposite colours cut that cycle into two arcs of even length, each of which tiles by walking along it. The page checks it by exhaustion: 1,024 of 1,024 on the 8×8, 324 of 324 on the 6×6.

That theorem has a direct consequence for play: on a bare rectangle, no first move can be a mistake. Laying a domino removes one dark and one light adjacent cell, which is exactly Gomory's hypothesis, so all 112 opening moves on an 8×8 are safe and there is nothing to think about. Punch two holes and the guarantee evaporates — 20.0% of boards already contain a move that ends the puzzle. At four holes it is 43.3%, at eight 86.7%, and at sixteen holes every board has one and 30.1% of all legal moves are fatal. The game does not begin until the theorem stops applying.

Remove two of each colour instead of one and the guarantee is simply gone: 10.20% of such 4×4 boards are dead, 4.96% of 4×6, 2.31% of 6×6 — 540 dead boards out of 23,409, every one of them perfectly balanced.

What a local test can see, and what it cannot

A fatal move is fatal for a reason, and the question is whether the reason is visible from close up. Three tests, in increasing strength, applied to the position after each fatal move on 119 real 8×8 boards:

  • an isolated cell — a free cell with no free neighbour left. Catches 26.2%.
  • a broken colour count — catches 0.0%, and always will.
  • a component with the wrong colour count — catches another 8.0%.

That leaves 65.8% of fatal moves invisible to all three: the board is still connected where it matters, every cell still has neighbours, every component is still balanced, and the puzzle is already over. There is no cheap test hiding behind those numbers — the obstruction is a Hall violation, and finding one is the same work as counting.

The same holds in the other direction. Of the 752 forced dominoes on those boards — dominoes every finish contains, which you may as well play immediately — the local rule “a cell with exactly one free neighbour” sees only 30.1%. Seven out of ten free moves are invisible without the count.

The claim that inverted: on a real puzzle the count buys nothing

Here is what this page was supposed to be. A board with exactly one tiling has, by definition, every domino forced: for each one, the number of finishes containing it equals the total, which is 1. So the counting engine solves a unique puzzle without ever guessing. I expected to find boards where all of that is true and the local rule is stuck at move one — every move forced, and no rule short of a full count able to name a single one.

Those boards do not exist. Swept exhaustively: all 65,536 boards of a 4×4, all 262,144 of a 3×6, and — behind the deep-sweep button — all 1,048,576 of a 4×5. Among them 17,817 connected boards with exactly one tiling, 5,337 of which are counted before you touch anything. Number with no cell of degree one to start from: 0. Number where repeated degree-one forcing failed to finish the board: 0.

And it is not luck. Orient every domino of the unique tiling one way and every other adjacency the other; a directed cycle in that orientation would be an alternating cycle, and flipping it would produce a second tiling. So the orientation is acyclic, an acyclic digraph has a sink, and a sink is a cell with exactly one free neighbour. Remove that forced pair and the remainder is still uniquely tileable, so the argument repeats. A uniquely-tileable board is always solvable by a rule with no arithmetic in it.

The step that does the work is bipartite, and the page carries the control that proves it: two triangles joined by a single edge have exactly one perfect matching, minimum degree 2, and no vertex a local rule can start from. Grids are bipartite; that graph is not.

So where is the count worth anything? Everywhere else

Four players, the same thirty solvable 8×8 puzzles with ten holes, each just laying dominoes until they are finished or stuck:

  • count — refuses any move that takes the number of finishes to zero: 100%. It cannot lose, and that is a theorem rather than a result.
  • component — takes forced pairs, refuses to isolate a cell, refuses to leave a component with the wrong colour count: 70.0%.
  • local — takes forced pairs, refuses to isolate a cell: 63.3%.
  • random — any legal domino: 0.0%. Not a low number, zero: it finished none of the thirty boards it was handed, all of which were solvable.

That is the honest shape of the result. On the one class of position where a puzzle is a puzzle — a unique answer — exact counting is worth nothing at all against a one-line rule. On every other position it is the difference between always and never.

A count answers questions a solver cannot ask

Once you have the number, three more things fall out for free, and none of them are available to a solver that only finds one tiling.

A uniform random tiling in one sweep. Run the recursion backwards to get, for every cursor position and frontier, the number of ways to finish from there. Then walk forwards taking each branch with probability proportional to that number. No rejection sampling, no Markov chain, no burn-in: one pass, exactly uniform over all 12,988,816 tilings.

The exact probability of every domino. Multiply the ways to arrive at a state by the ways to finish from it and you get the number of tilings routed through that state, and hence the number containing each domino, in one forward and one backward sweep instead of one whole DP per domino. Both are computed on this page and compared; they agree to the unit.

And the answer is not what you would guess. On a bare 8×8 the intuition is that every domino is roughly as likely as every other. Measured, the probabilities run from 0.1698 to 0.5000 — a factor of 2.94 — with the corner dominoes at exactly one half, because a corner cell has two neighbours and the board is symmetric. The mean is exactly (cells / 2) / edges = 2/7, which is not a measurement but an identity: each of the 32 dominoes in a tiling is one of the 112 edges. And on a 2×n strip the probability that the far end is closed off by a single upright domino is F(n)/F(n+1), which at n = 20 reads 0.618033985 against 1/φ = 0.6180339887.

Two more numbers that are not what they look like

Doubles. The DP runs in Float64Array, which holds exact integers only below 253 = 9,007,199,254,740,991. The obvious guess is that it starts lying when the answer passes that line. It does not. A 12×12 board has 53,060,477,521,960,000 tilings — nearly six times over the limit — and the double DP returns it exactly, because every partial sum on the way lands on a representable value. The first rectangle where it is wrong is 10×14, at 16,848,161,392,724,969, where it returns …968: off by one, in a number three times smaller than one it got right. Magnitude does not predict precision; the page carries a BigInt DP alongside and prints where the two part company rather than guessing.

Symmetry. A 6×6 board has 6,728 tilings, and the natural way to count them up to rotation and reflection is to divide by the eight symmetries of the square: 841. The true answer is 930. Burnside's lemma says average the fixed points, not the elements, and the fixed-point counts are lopsided — on a 6×6, the two quarter turns fix zero tilings and so do both diagonal reflections, leaving only the half turn (120) and the two axis reflections (296 each) contributing anything at all. On a 4×4 the naive division gives 4.5, which is not even an integer, against a true 9. The page computes both the lemma and the explicit orbits and checks them against each other.

What the engine returns

countTilings(board)          -> the exact number of ways to finish       (2^W states)
classifyMoves(board)         -> every legal domino, with its count, and
                                dead = 0, forced = equals the total
edgeOdds(board)              -> the exact probability of each domino
sampleTiling(board, layers)  -> one uniformly random tiling, one pass
isTileableByMatching(board)  -> yes / no, with no count anywhere in it

🔨 How it is built

1. The whole engine

function countTilings(b){
  const W = b.W, H = b.H, S = 1 << W, free = b.free;
  let dp = new Float64Array(S), nd = new Float64Array(S);
  dp[0] = 1;
  const TOP = 1 << (W - 1);
  for (let r = 0; r < H; r++)
    for (let c = 0; c < W; c++){
      nd.fill(0);
      const p = r * W + c;
      const canR = c + 1 < W && free[p + 1] === 1;
      const canD = r + 1 < H && free[p + W] === 1;
      for (let m = 0; m < S; m++){
        const v = dp[m];
        if (v === 0) continue;
        if ((m & 1) || free[p] === 0){ nd[m >> 1] += v; continue; }   // covered, or a hole
        if (canR && !(m & 2)) nd[(m | 2) >> 1] += v;                  // lay it rightwards
        if (canD)             nd[(m >> 1) | TOP] += v;                // lay it downwards
      }
      const t = dp; dp = nd; nd = t;
    }
  return dp[0];
}

Twenty lines, and it counts the tilings of any region with holes anywhere. The two interesting lines are the two placements: rightwards marks the cell next door, which is bit 1; downwards marks the cell below, which is bit W and therefore the top bit once the mask shifts. Get that shift backwards and you have a program that counts something else and never says so.

2. The check that matters, on every board

// no frontier, no mask, no compression - the thing the DP claims to equal
function enumTilings(b){
  const cov = b.free.slice();
  let count = 0;
  (function rec(start){
    let p = start; while (p < N && !cov[p]) p++;
    if (p === N){ count++; return; }
    if (right is free){ cover both; rec(p + 1); uncover both; }
    if (below is free){ cover both; rec(p + 1); uncover both; }
  })(0);
  return count;
}
// then, for all 65,536 boards of a 4x4:
//   countTilings(b) === enumTilings(b)          and
//   isTileableByMatching(b) === (countTilings(b) > 0)

Two solvers with nothing in common and a third that answers a weaker question by a completely different mechanism. All 65,536 boards, 0 disagreements, and 1,048,576 more behind the deep-sweep button.

3. Backwards, for everything else

suffix[p][m] = ways to FINISH from cursor p with pending frontier m
prefix[p][m] = ways to ARRIVE at cursor p carrying frontier m

count           = suffix[0][0]
tilings through a state = prefix[p][m] * suffix[p][m]
odds of a domino        = sum over m of prefix[p][m] * suffix[p+1][after placing it]  /  count
a uniform sample        = walk forwards, branch with probability proportional to suffix

One extra backward pass turns a counter into a sampler, a probability table and a forced-move oracle. The sampler is exactly uniform in a single sweep with no rejection and no chain, which is the part that surprises people: counting a set is what lets you draw from it fairly.

4. The move oracle, in full

dead   = the number of tilings containing this domino is 0
forced = that number EQUALS the total
odds   = that number / the total

Compared as integers, never as ratios. A ratio of 0.9999999999 and a count that equals the total are different claims, and only one of them means “every finish uses this”. The same numbers are also computed the slow, obvious way — delete the two cells and run a whole fresh DP — and the two agree exactly on every edge of a 6×6.

5. Three local tests, written to be given their best shot

isolated  : some free cell has no free neighbour            -> degreeOneCells() returns null
unbalanced: dark count != light count                        -> balanceOf().diff
component : some connected component has diff != 0           -> componentsBalanced()

Each fatal move is charged to the first test that catches it, so the numbers do not double-count, and the strongest test gets the leftovers. The unbalanced row reads 0 in every configuration; that is not a bug in the harness, it is the point.

6. The generator is the engine

// punch out colour-balanced pairs, always keeping the count above zero,
// always taking the pair that shrinks the count the most, until one tiling is left
for (;;){
  best = argmin over sampled (dark, light) pairs of countTilings(board without them)
  if (best count is 0 or none found) stop
  board = board without best;  if (count === 1) stop
}

Nothing in that loop knows what a puzzle is. It knows how to count, and “a puzzle” is the fixed point of counting downwards.

7. The race, and why the count player cannot lose

count     : filter the legal moves to those with countTilings(after) > 0, pick any
component : take a forced pair if one exists, else any move that isolates nobody
            and leaves every component balanced
local     : the same without the component test
random    : any legal domino

The count player winning 100% is not evidence about the count player; it is a restatement of what the count is. The number worth reading is the one underneath it, and it is 0.0%.

8. Burnside, checked rather than applied

orbits = (1 / |G|) * sum over g in G of |{ tilings fixed by g }|      // the lemma
// and, separately, the orbits built explicitly by canonical form
// 4x4: 36 tilings, group 8, fixed 36/2/8/2/12/12/0/0 -> 9, and 9 orbits found
// 6x6: 6,728 tilings -> 930, against 6728/8 = 841

9. Two arithmetics, because one of them lies

countTilings(b)     // Float64Array  - fast, exact below 2^53 and sometimes far past it
countTilingsBig(b)  // BigInt        - always exact, roughly 40x slower
// the page runs both across a table of rectangles and reports the FIRST disagreement
// rather than assuming a bound: it is 10x14, not the 12x12 that is six times larger

10. What this engine is not

// Exact and total for any region that fits in a W-bit frontier: cost is H * 2^W * W.
// W = 14 is comfortable, W = 20 is not - this is exponential in the WIDTH, which is why
// the boards here are narrow-or-square and never 4 x 400 in the wrong orientation.
// It counts DOMINO tilings only. Trominoes, polyomino packings and coloured dominoes each
// need a different frontier, and the same idea does not simply widen to cover them.
// It is not a two-player game: there is no opponent, and nothing here is a search.
