GAME OVER

Each fruit is a projectile: it is thrown up from below the screen with an upward velocity and a sideways nudge, then a single line of gravity added every tick bends its path into a parabola so it rises, slows, and falls. The blade is nothing but the last few positions of your pointer, joined into a line; when the newest segment of that line passes within a fruit's radius of its centre — a segment-versus-circle test — the fruit is cut. Slicing spawns two spinning halves and a burst of juice that obey the same gravity, and a fixed-timestep loop runs the whole simulation in constant 1/120 s steps so it plays the same on any monitor.

🔨 Build it yourself

    
Fruit Ninja looks like it needs sprites and a physics engine, but it is really just four small ideas stacked together: a fruit is a projectile thrown up from below that gravity pulls back into an arc, the blade is the last few points your pointer visited joined into a line, a slice is a single segment-versus-circle distance test, and a cut spawns two halves plus juice particles that fall under the same gravity. Chain the slices in one motion for a combo, hide a bomb among the fruit for danger, and count three mistakes as game over. Below is the whole game in eight short blocks. Copy them in order.

    
    

      
  1. 
        
    1
    A fruit is a projectile launched from below
    
        
    There are no paths to script. A fruit is a circle with a position and a velocity, spawned just below the bottom edge at a random column and thrown upward with a strong negative vertical velocity and a small sideways nudge aimed roughly toward the middle. That is all the launch is — from here gravity does the rest, so the fruit rises, slows, stops, and falls in a parabola. A small fraction of spawns are bombs instead of fruit.
    
        
    const GRAVITY = 900;                    // px/s^2, pulls everything down
const FRUITS = [ {color:"#ef4444",r:38}, {color:"#f97316",r:30}, /* … */ ];

function spawnOne(){
  const bomb = Math.random() < 0.12;    // ~1 in 8 is a bomb
  const type = bomb ? "bomb" : (Math.random() * FRUITS.length | 0);
  const r    = bomb ? 30 : FRUITS[type].r;
  const x = rand(W * 0.15, W * 0.85);    // random column
  const y = H + r + 10;                  // start just below the screen
  const vy = -rand(680, 860);            // thrown UP (negative y)
  const vx = clamp((W / 2 - x) * 0.6, -260, 260) + rand(-60, 60); // toward centre
  fruits.push({ x, y, vx, vy, r, type, rot:0, vrot:rand(-3,3), sliced:false });
}

    The fixed-timestep loop and the parabolic arc
    
        
    Advance the physics by however long the last frame took and the fruit fly higher on a slow machine than a fast one. The fix is an accumulator: bank the real elapsed time and spend it in fixed 1/120 s chunks. Inside each chunk the arc is two lines — add gravity to the vertical velocity, then add both velocities to the position. Rise, slow, fall: a perfect parabola for free.
    
        
    const STEP = 1 / 120;
let last = performance.now(), acc = 0;
function frame(now){
  let dt = (now - last) / 1000; last = now;
  if (dt > 0.25) dt = 0.25;              // clamp a tab-switch / lag spike
  acc += dt;
  while (acc >= STEP){ update(STEP); acc -= STEP; }  // fixed slices
  render(); requestAnimationFrame(frame);
}
function stepFruit(f, dt){
  f.vy += GRAVITY * dt;                   // gravity — the whole of the arc
  f.x  += f.vx * dt;                      // integrate position from velocity
  f.y  += f.vy * dt;
  f.rot += f.vrot * dt;                   // a little spin for flavour
}

    3
    The blade is your recent pointer trail
    
        
    There is no sword sprite. The blade is just an array of the last places your pointer has been, each stamped with a time. Every time the pointer moves you push a new point and drop any older than a tenth of a second, so the trail is always a short, fresh ribbon that you draw as a fading, tapering line. The important part is that each new point, paired with the one before it, is a line segment — the segment your hand just swept.
    
        
    let trail = [];                           // [{x, y, t}, …] newest last
const TRAIL_MS = 130;

function addTrailPoint(x, y){
  const now = performance.now();
  const prev = trail[trail.length - 1];
  trail.push({ x, y, t: now });
  if (trail.length > 40) trail.shift();
  // only a *fresh* move is a real swipe — a big time gap is a pen-up, ignore it
  if (playing && prev && now - prev.t < 60) sliceSegment(prev.x, prev.y, x, y);
}
// prune old points each frame so the ribbon stays short
function pruneTrail(now){ while (trail.length && now - trail[0].t > TRAIL_MS) trail.shift(); }

    The slice test — shortest distance from a point to a segment
    
        
    This is the heart of the whole game. A fruit is a circle; the swipe is a line segment; the fruit is cut when the segment passes within the fruit's radius of its centre. Finding that distance is the classic trick: project the centre onto the infinite line through the segment to get a parameter t, then clamp t to [0,1] so you land on the closest point of the segment (not the endless line), and compare that point's distance to the radius. Compare squared distances and there is not even a square root.
    
        
    function segCircle(ax, ay, bx, by, cx, cy, r){
  const dx = bx - ax, dy = by - ay;         // the swipe segment A→B
  const len2 = dx*dx + dy*dy;
  let t = len2 ? ((cx-ax)*dx + (cy-ay)*dy) / len2 : 0;  // project C onto A→B
  t = t < 0 ? 0 : t > 1 ? 1 : t;             // clamp to the segment's ends
  const px = ax + t*dx, py = ay + t*dy;      // closest point on the segment
  const ex = cx - px, ey = cy - py;
  return ex*ex + ey*ey <= r*r;               // within the radius? → a hit
}
function sliceSegment(ax, ay, bx, by){
  for (const f of fruits){
    if (f.sliced) continue;
    if (segCircle(ax, ay, bx, by, f.x, f.y, f.r))
      f.type === "bomb" ? hitBomb(f) : sliceFruit(f, ax, ay, bx, by);
  }
}

    5
    A cut splits the fruit into two halves and juice
    
        
    When a fruit is sliced it is removed and replaced by two half-discs, thrown apart perpendicular to the cut so they fly off to either side of the blade, spinning, and falling under the same gravity. A dozen small juice droplets in the fruit's colour burst out in every direction. Halves and particles are the same projectile as the fruit — position, velocity, gravity — just with a lifetime so they fade and are cleared away.
    
        
    function sliceFruit(f, ax, ay, bx, by){
  f.sliced = true; score += 1; registerComboSlice();
  const ang  = Math.atan2(by - ay, bx - ax);   // direction of the blade
  const perp = ang + Math.PI / 2;              // halves fly across the cut
  for (const side of [-1, 1])
    halves.push({ x:f.x, y:f.y, r:f.r, type:f.type, ang, side, rot:0, vrot:rand(-4,4),
      vx: f.vx*0.4 + Math.cos(perp)*120*side,
      vy: f.vy*0.4 + Math.sin(perp)*120*side - 40, life:1.6 });
  for (let i = 0; i < 14; i++){                 // juice particles
    const a = Math.random()*Math.PI*2, sp = rand(40, 220);
    particles.push({ x:f.x, y:f.y, vx:Math.cos(a)*sp, vy:Math.sin(a)*sp - 60,
      r:rand(2,6), color:FRUITS[f.type].inner, life:rand(0.5,1.0) });
  }
}

    6
    Combos — chain slices in one unbroken motion
    
        
    A combo is just "how many fruit fell to the blade in quick succession". Every slice bumps a counter and refreshes a short timer; while your blade keeps cutting, the timer keeps being reset and the count climbs — a single swipe across three fruit registers three slices in the same tick. When the timer finally lapses with no new cut, the streak is over: three or more earns a bonus and a flashy pop-up, then the counter resets to zero.
    
        
    const COMBO_WINDOW = 0.30;                 // seconds a combo stays "alive"
let combo = 0, comboTimer = 0;

function registerComboSlice(){             // called once per fruit sliced
  combo += 1; comboTimer = COMBO_WINDOW;   // keep the streak alive
}
function tickCombo(dt){
  if (combo > 0 && (comboTimer -= dt) <= 0){ // streak ended
    if (combo >= 3){                        // 3+ in one motion → bonus
      const bonus = combo * 2; score += bonus;
      comboPopup = { n: combo, bonus, life: 1.1 };
    }
    combo = 0;
  }
}

    7
    Bombs, missed fruit, and three lives
    
        
    There are two ways to lose a life. Touch a bomb with the blade and it explodes — that is the same slice test as a fruit, only the outcome is a penalty. Or let a fruit fall clean off the bottom of the screen without cutting it. Each mistake costs one of three lives; run out and the game is over. Fruit that drift off the sides, and bombs that fall away untouched, are simply removed and cost nothing.
    
        
    function hitBomb(f){ f.sliced = true; explode(f); loseLife(); }

function cull(){                            // once per tick, after the physics
  for (let i = fruits.length - 1; i >= 0; i--){
    const f = fruits[i];
    if (f.sliced){ fruits.splice(i, 1); continue; }
    if (f.y - f.r > H + 40 && f.vy > 0){    // fell off the BOTTOM…
      if (f.type !== "bomb") loseLife();     // …a missed fruit costs a life
      fruits.splice(i, 1);
    } else if (f.x < -80 || f.x > W + 80){   // drifted off a side → free
      fruits.splice(i, 1);
    }
  }
}
function loseLife(){ if (--lives <= 0) gameOver(); }

    Wiring it together — the tick and the pointer
    
        
    The update tick spawns a fresh wave on a timer, steps every fruit, half and particle through the arc, ages the combo, and culls what has left the field — slicing itself happens off in the pointer handler as your hand moves. The one fiddly bit is mapping the pointer: the canvas is drawn at a fixed 832×448 but shown at whatever CSS width, so scale the client coordinates by the ratio between the two before you feed them to the blade.
    
        
    function update(dt){
  if ((spawnTimer -= dt) <= 0){ spawnWave(); spawnTimer = rand(0.65, 1.25); }
  for (const f of fruits)    stepFruit(f, dt);
  for (const h of halves)    { stepFruit(h, dt); h.life -= dt; }
  for (const p of particles) { stepFruit(p, dt); p.life -= dt; }
  tickCombo(dt); cull();
}
function canvasPos(e){                       // client px → internal 832×448
  const b = canvas.getBoundingClientRect();
  return { x:(e.clientX - b.left) * (canvas.width  / b.width),
           y:(e.clientY - b.top ) * (canvas.height / b.height) };
}
canvas.addEventListener("pointermove", e => {
  const p = canvasPos(e); addTrailPoint(p.x, p.y); e.preventDefault();
}, { passive:false });
