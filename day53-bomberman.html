Blow up the crates, trap the hunters, don't stand in your own fire.

You are the white bomber in the top-left corner. Walk with the arrow keys or WASD, drop a bomb with Space. A bomb ticks for two seconds, then bursts into a cross of fire that reaches a few tiles in each direction — it smashes the brown soft crates (and stops at the one it breaks), but a grey stone pillar stops it cold and can never be destroyed. The blast kills anything it touches, including you. Purple hunters path straight toward you through the corridors — herd them into a dead end, lay a bomb, and step away. Clear every hunter to win; get caught by a hunter or a flame and it's over.

🔨 Build it yourself

    
Bomberman looks like it needs sprites, collision physics and enemy scripting; it needs a 2D array of integers and three ideas — a countdown, a ray-cast, and a breadth-first search. The board is one grid where 0 is floor, 1 is stone, 2 is a crate. A bomb is a cell with a fuse. An explosion walks outward from that cell and stops at walls. An enemy floods the floor to find you. Everything else is drawing. About 250 lines of vanilla JavaScript on one canvas, no libraries. Copy each block in order.

    
    

      
  1. 
        
    1
    The arena is a 2D array of integers
    
        
    Forget tiles and sprites — the whole board is grid[row][col] holding one of three numbers: 0 floor you can walk on, 1 stone you can't pass or break, 2 a soft crate you can blow up. The classic Bomberman layout is not random: the outer ring is stone, and inside there is an unbreakable pillar on every cell whose row and column are both even. That checkerboard is the whole reason the board can never seal shut — the odd rows and columns are always open lanes.
    
        
    const COLS = 15, ROWS = 13;      // odd sizes → the classic pillar grid
const EMPTY = 0, HARD = 1, SOFT = 2;
let grid = [];

function buildGrid(){
  grid = [];
  for (let r = 0; r < ROWS; r++){
    grid[r] = [];
    for (let c = 0; c < COLS; c++){
      const border = r === 0 || c === 0 || r === ROWS-1 || c === COLS-1;
      const pillar = r % 2 === 0 && c % 2 === 0;   // even row AND even col
      grid[r][c] = (border || pillar) ? HARD : EMPTY;
    }
  }
}
    
      
    2. 

      
  2. 
        
    2
    Scatter crates — but keep the corners safe
    
        
    Fill the open floor with soft crates at random, roughly three cells in four, so the maze is dense but the odd lanes give it structure. The one rule that stops the game being unfair: never brick a spawn shut. Reserve each of the four corners and the two cells next to each corner as guaranteed floor, so the bomber and every hunter start with a way out. Because crates are destructible, the rest of the board opens up as you play.
    
        
    function scatterCrates(reserved){
  for (let r = 0; r < ROWS; r++)
    for (let c = 0; c < COLS; c++)
      if (grid[r][c] === EMPTY && !reserved.has(c + "," + r) && Math.random() < 0.75)
        grid[r][c] = SOFT;                       // brown breakable crate
}
// reserved = the 4 corners + each corner's two orthogonal neighbours,
// so nobody is ever boxed in at spawn.
    
      
    3. 

      
  3. 
        
    3
    Move one tile at a time — you can never enter a wall or a bomb
    
        
    Everyone — the bomber and the hunters — lives on a cell and tweens smoothly to the next one. All of movement collapses into a single predicate: canEnter. A target cell is enterable only if it is on the board, it is floor (not stone, not a crate), and it has no bomb sitting on it. That last clause is the neat trick for standing on your own freshly-dropped bomb: you're never entering the cell you're already on, so you can walk off it, but neither you nor a hunter can ever walk back onto a bomb.
    
        
    function inBounds(c, r){ return c >= 0 && c < COLS && r >= 0 && r < ROWS; }
function bombAt(c, r){ return bombs.find(b => b.col === c && b.row === r); }

function canEnter(c, r){
  return inBounds(c, r) && grid[r][c] === EMPTY && !bombAt(c, r);
}
function startMove(e, dc, dr){                   // begin a tween to the neighbour
  if (e.moving || !canEnter(e.col + dc, e.row + dr)) return false;
  e.tc = e.col + dc; e.tr = e.row + dr;          // target cell
  e.moving = true; e.t = 0; e.dir = { dc, dr };
  return true;
}
    
      
    4. 

      
  4. 
        
    4
    A bomb is a cell with a countdown
    
        
    Dropping a bomb is pushing one object — a cell, a two-second fuse, and the blast range you carry. You can only drop while you have a bomb in reserve (max bombs minus the ones already ticking) and only if there isn't one on your tile already. Every frame each fuse loses the elapsed time; when it hits zero the bomb explodes. The bomb becomes solid the instant you step off it, because canEnter already refuses any cell with a bomb on it.
    
        
    const FUSE = 2.0;                                 // seconds before it blows
let bombs = [];

function dropBomb(){
  const cell = occupantCell(player);
  if (bombs.length >= maxBombs || bombAt(cell.c, cell.r)) return;
  bombs.push({ col: cell.c, row: cell.r, timer: FUSE, range: bombRange });
}
function tickBombs(dt){
  for (const b of bombs) b.timer -= dt;
  for (const b of bombs) if (b.timer <= 0) explode(b);   // fuse burned out
  bombs = bombs.filter(b => !b.exploded);
}
    
      
    5. 

      
  5. 
        
    5
    The explosion — a ray-cast in four directions
    
        
    This is the heart of Bomberman. Light the bomb's own cell, then shoot a ray down each of the four directions, one tile at a time, up to the blast range. Each step asks the tile ahead one question. Off the board or stone? Stop — the arm ends here, nothing behind it burns. A crate? Break it into floor, set that one tile alight, and stop — the blast destroys exactly one crate per arm and goes no further. Otherwise it's floor: set it alight and keep going. And if a lit tile holds another bomb, detonate it too — that single recursive line is the whole chain reaction.
    
        
    function explode(b){
  if (b.exploded) return;
  b.exploded = true;
  addFire(b.col, b.row);                          // the bomb's own cell
  for (const [dc, dr] of [[1,0],[-1,0],[0,1],[0,-1]]){
    for (let i = 1; i <= b.range; i++){
      const c = b.col + dc*i, r = b.row + dr*i;
      if (!inBounds(c, r) || grid[r][c] === HARD) break;   // stone blocks it
      if (grid[r][c] === SOFT){ grid[r][c] = EMPTY; addFire(c, r); break; }
      addFire(c, r);                              // empty floor: burn + continue
      const chained = bombAt(c, r);
      if (chained && !chained.exploded) explode(chained);   // chain reaction
    }
  }
}
    
      
    6. 

      
  6. 
        
    6
    Hunters that chase — breadth-first search
    
        
    A hunter isn't scripted with "if player is left, go left" — it actually pathfinds. Every time it needs a move it runs a breadth-first search from its own cell across the floor tiles, recording where it first reached each cell, until it touches the bomber's tile. Then it walks that chain of parents back to find the very first step of the shortest path and takes just that one step. BFS on a 15×13 grid is instant, and because it re-plans every step, the hunter follows you around corners. A pinch of random wander keeps it beatable.
    
        
    function bfsStep(sc, sr, tc, tr){
  const q = [[sc, sr]], prev = {}, seen = new Set([sc + "," + sr]);
  let found = false;
  while (q.length){
    const [c, r] = q.shift();
    if (c === tc && r === tr){ found = true; break; }
    for (const [dc, dr] of [[1,0],[-1,0],[0,1],[0,-1]]){
      const nc = c+dc, nr = r+dr, k = nc + "," + nr;
      if (seen.has(k) || !inBounds(nc,nr) || grid[nr][nc] !== EMPTY || bombAt(nc,nr)) continue;
      seen.add(k); prev[k] = [c, r]; q.push([nc, nr]);   // remember who found it
    }
  }
  if (!found) return null;
  let cur = [tc, tr];                               // walk parents back to the start
  while (prev[cur[0]+","+cur[1]]){
    const p = prev[cur[0]+","+cur[1]];
    if (p[0] === sc && p[1] === sr) return [cur[0]-sc, cur[1]-sr];  // first step
    cur = p;
  }
  return null;
}

  7. 
        
    7
    Win, lose, and the game loop
    
        
    Every frame after moving everyone: any hunter standing on a burning tile is removed from the array; if the bomber is on a burning tile, or a hunter shares his cell, the game is lost; and if the hunter array is empty, you've won. That's the entire outcome logic — three checks against the fire set and the enemy list. Wrap it in one requestAnimationFrame loop that measures the real elapsed time so fuses and movement run at the same speed on every machine.
    
        
    function resolve(){
  const p = occupantCell(player);
  enemies = enemies.filter(e => !fireAt(occupantCell(e)));   // flames kill hunters
  if (fireAt(p)) return lose("caught in the blast");
  for (const e of enemies)
    if (occupantCell(e).c === p.c && occupantCell(e).r === p.r) return lose("a hunter got you");
  if (enemies.length === 0) win();
}
function loop(ts){
  const now = ts / 1000, dt = Math.min(0.05, now - last); last = now;
  if (phase === "play"){ update(dt); resolve(); }
  render();
  requestAnimationFrame(loop);
}
