🔨 Build it yourself

    
Mastermind looks like it needs a rules engine; it needs a grade-school counting trick. The secret is an array of four numbers. A guess is an array of four numbers. The entire game is one scoring function that turns a guess into two tallies — blacks and whites — plus a little UI to place pegs and a loop that runs out of tries. About 150 lines of vanilla JavaScript, no libraries, no canvas even. Copy each block in order.

    1
    Colours are just numbers — the whole state is two arrays
    
        
    Forget "red" and "blue" — a colour is an index, 0 to 5. That one decision makes everything downstream trivial: the secret code is an array of four indices, a guess is an array of four indices, and comparing them is comparing numbers. The palette is the only place a colour ever becomes a real hex value, for drawing. Keep the game logic in integers.
    
        
    const COLORS = [                                  // index → paint
  {name:"Red",hex:"#ef4444"}, {name:"Orange",hex:"#f97316"},
  {name:"Yellow",hex:"#eab308"}, {name:"Green",hex:"#22c55e"},
  {name:"Blue",hex:"#3b82f6"}, {name:"Purple",hex:"#a855f7"},
];
const CODE_LEN = 4;          // pegs per row
let colorCount = 6;          // how many colours are in play
let maxRows    = 10;         // guesses allowed

let secret  = [];            // the hidden code, e.g. [4,0,4,2]
let rows    = [];            // submitted guesses + their scores
let current = [null,null,null,null];  // the row you're editing
let armed   = 0;             // colour picked from the palette

    2
    The heart: a duplicate-safe two-pass score
    
        
    This is the only clever function in the game, and the one everybody gets wrong on the first try. Pass one: walk both rows together and count every hole where the colour matches exactly — that's a black peg — and for the holes that don't match, tally the leftover colours on each side. Pass two: for each colour, the white pegs it earns is the smaller of "how many the guess has left" and "how many the code has left". Because exact matches are removed first and each side is only counted by its remainder, no peg is ever double-counted — that's what makes duplicates correct.
    
        
    function scorePegs(guess, code){
  let black = 0;
  const codeLeft = {}, guessLeft = {};        // leftover colour tallies
  for (let i = 0; i < code.length; i++){
    if (guess[i] === code[i]) black++;         // exact hit → black
    else {                                     // otherwise bank the colours
      codeLeft [code[i]]  = (codeLeft [code[i]]  || 0) + 1;
      guessLeft[guess[i]] = (guessLeft[guess[i]] || 0) + 1;
    }
  }
  let white = 0;
  for (const c in guessLeft)                    // match the remainders by colour
    white += Math.min(guessLeft[c], codeLeft[c] || 0);
  return { black, white };
}

    Placing pegs — fill the active row
    
        
    Building a guess is just writing indices into the current array. Click a palette swatch to arm a colour, click a hole to drop it there, right-click to clear a hole. Number keys are the fast path — they arm a colour and drop it into the leftmost empty hole so you can type a guess. Backspace lifts the last peg. None of this touches the code; it only edits one array of four numbers.
    
        
    function placeAt(i){ current[i] = armed; render(); }   // click a hole
function clearAt(i){ current[i] = null;  render(); }   // right-click

function fillNext(colorIdx){                            // number-key fast path
  armed = colorIdx;
  const i = current.indexOf(null);
  if (i !== -1) current[i] = colorIdx;
  render();
}
function removeLast(){
  for (let i = current.length-1; i >= 0; i--)
    if (current[i] !== null){ current[i] = null; break; }
  render();
}

    4
    Submit a guess — score, then win or lose
    
        
    Checking is three lines of decision. Refuse the guess if any hole is still empty. Otherwise score it against the secret and push the row with its two peg counts. Four black pegs means every peg is right in place — you've cracked it. If not and you've used your last row, the game is lost and the code is revealed. Reset the editable row and let the player read the new clue.
    
        
    function check(){
  if (current.some(c => c === null)) return flash("Fill all four holes");
  const { black, white } = scorePegs(current, secret);
  rows.push({ guess: current.slice(), black, white });
  if (black === CODE_LEN)      phase = "won";           // all pegs exact
  else if (rows.length >= maxRows) phase = "lost";      // out of tries
  current = Array(CODE_LEN).fill(null);
  render();
}

    Draw the board — rows of holes and peg feedback
    
        
    The board is pure derived HTML: for each of the ten rows, either a submitted guess with its black/white pegs, the one active editable row, or an empty row waiting. A peg-hole is a coloured circle; the feedback is a little 2×2 of dots — black first, then white, then empty. Rebuild the whole thing from state on every change; there is so little of it that re-rendering costs nothing and there's no stale UI to chase.
    
        
    function feedback(black, white){
  let dots = "";
  for (let i = 0; i < CODE_LEN; i++){
    const cls = i < black ? "black" : i < black+white ? "white" : "none";
    dots += `<div class="mm-fbdot ${cls}"></div>`;
  }
  return `<div class="mm-fb">${dots}</div>`;
}
function hole(idx, editable){
  if (idx === null) return `<div class="mm-hole empty"></div>`;
  return `<div class="mm-hole filled" style="background:${COLORS[idx].hex}"></div>`;
}

    A fresh secret — random code, new game
    
        
    Starting a round is choosing a secret. Pick four random colour indices; if you've turned duplicates off, reject any colour already used so every peg is distinct. Then wipe the rows, reset the editable buffer, and set the phase to playing. That's the entire reset — because the game is those few variables, resetting them is the same as building a whole new board.
    
        
    function makeSecret(){
  const s = [];
  while (s.length < CODE_LEN){
    const c = Math.floor(Math.random() * colorCount);
    if (allowDup || !s.includes(c)) s.push(c);         // distinct if no-dup
  }
  return s;
}
function newGame(){
  secret  = makeSecret();
  rows    = [];
  current = Array(CODE_LEN).fill(null);
  phase   = "play";
  render();
}

    Flip sides — the AI codebreaker (Knuth's minimax)
    
        
    The same score function that grades you lets the computer break your code. Start with the set of all 1296 possible codes. After each guess, keep only the codes that would have produced the exact same black/white score — the rest are logically impossible. To choose the next guess, Knuth's rule is minimax: for every candidate guess, look at how the remaining set would split across all possible scores, and pick the guess whose largest resulting group is smallest — the guess that guarantees the biggest cut no matter what the feedback turns out to be. It cracks any 4×6 code in five guesses or fewer.
    
        
    let S = allCodes(CODE_LEN, colorCount);   // every possibility, all 1296
let guess = [0,0,1,1];                     // Knuth's proven opener

function aiStep(){
  const { black, white } = scorePegs(guess, secret);
  rows.push({ guess: guess.slice(), black, white });
  if (black === CODE_LEN) return;                       // solved
  S = S.filter(c => {                                    // drop the impossible
    const s = scorePegs(guess, c);
    return s.black === black && s.white === white;
  });
  let bestWorst = Infinity;                              // minimax pick
  for (const g of allCodes(CODE_LEN, colorCount)){
    const buckets = {};
    for (const c of S){ const k = scorePegs(g,c); buckets[k.black+"-"+k.white] = (buckets[k.black+"-"+k.white]||0)+1; }
    const worst = Math.max(...Object.values(buckets));   // worst-case group
    if (worst < bestWorst){ bestWorst = worst; guess = g; }
  }
  setTimeout(aiStep, 700);
}

🎉 Day 52 of GameFromZero done — the code-breaking classic.
You built the whole of Mastermind with no rules engine underneath — a secret that is four numbers, a guess that is four numbers, and one scoring function that grades them in two passes: an exact-match sweep for the black pegs, then a leftover-colour count for the whites, so duplicate colours are handled correctly and no peg is ever counted twice. Those two little tallies are the only information in the game, and from them you deduce a code hiding among 1296 possibilities. Turn it around and the same function powers Knuth's minimax solver, which cracks any code in five guesses by always choosing the guess that shrinks the worst-case remaining set the most.
