🔨 Build it yourself

    
Pipe Mania looks like it needs a graph library and a flood-fill, but it is really just five small ideas stacked together: a pipe piece is a set of open sides stored as four bits, a queue hands you random pieces to click onto a grid, a fuse counts down and then the water is released, the water is a little walker that each tick asks its current piece for its other opening, and it advances only when the neighbour has the opposite opening facing back. Get that one bitmask test right — neighbour.mask & opposite(exit) — and everything else (overwrite rules, a distance goal, win and lose) is a few lines each. Below is the whole game in eight short blocks. Copy them in order.

    
    

      
  1. 
        
    1
    A pipe piece is a set of open sides
    
        
    There are no sprites and no special cases per piece. A piece is just which of its four sides are open, packed into four bits — North 1, East 2, South 4, West 8. A horizontal straight has East and West open, so its mask is 2|8 = 10; an elbow from North to East is 1|2 = 3; the cross is all four, 15. That is the entire vocabulary of the game: every rule below is a bit test against these masks.
    
        
    const N = 1, E = 2, S = 4, W = 8;          // one bit per side

const PIECES = {
  H:  E | W,        // 10  ── straight ──
  V:  N | S,        //  5  │ straight │
  NE: N | E,        //  3  └ elbow
  SE: E | S,        //  6  ┌ elbow
  SW: S | W,        // 12  ┐ elbow
  NW: N | W,        //  9  ┘ elbow
  CROSS: N|E|S|W    // 15  ┼ crossover
};
// "is this piece open on side d?"  →  (mask & d) !== 0
function open(mask, d){ return (mask & d) !== 0; }

  2. 
        
    2
    Directions: opposites and grid deltas
    
        
    Two tiny lookup tables make the whole flow work. OPP maps a side to the side facing it — North↔South, East↔West — because when water leaves a cell heading East it enters the next cell through its West side. DELTA maps a side to the row/column step you take to reach that neighbour. Every "does the pipe connect?" and "where does the water go next?" question is answered with these two.
    
        
    const OPP   = { 1:4, 4:1, 2:8, 8:2 };        // N↔S, E↔W
const DELTA = { 1:[-1,0], 2:[0,1], 4:[1,0], 8:[0,-1] }; // [dr,dc]

// leaving a cell through `exit` → the neighbour cell…
const [dr, dc] = DELTA[exit];
const nr = r + dr, nc = c + dc;
// …and the water enters that neighbour through the OPPOSITE side
const entrySide = OPP[exit];

  3. 
        
    3
    The board, the source, and the random queue
    
        
    The world is a grid of cells, each either empty, a pipe (with a mask), or the one source — a special cell with a single opening that points into the board. A queue hands you the upcoming pieces one at a time, drawn from a weighted bag so straights and elbows are common and the cross is rare. You always place queue[0]; placing it shifts the queue forward and tops it back up.
    
        
    const COLS = 9, ROWS = 7;
let board = [];
for (let r = 0; r < ROWS; r++){
  board[r] = [];
  for (let c = 0; c < COLS; c++) board[r][c] = { kind:"empty", mask:0, filled:false };
}
// the source: one opening, pointing into the grid
let source = { r: 3, c: 0, dir: E };
board[3][0] = { kind:"source", mask: E, filled:false };

const BAG = ["H","H","H","V","V","V","NE","SE","SW","NW","NE","SE","SW","NW","CROSS"];
let queue = [];
function refill(){ while (queue.length < 5) queue.push(BAG[Math.random()*BAG.length | 0]); }
    
      
    4. 

      
  4. 
        
    4
    Placing a piece — and the overwrite rule
    
        
    Clicking a cell drops the front of the queue onto it. On an empty cell that is a plain place. On a cell that already holds a pipe it is an overwrite — allowed, because you are correcting your own plan — but only if the water has not yet reached it. You can never overwrite a cell the water has already filled, the cell it is filling right now, or the source. That single guard is the whole risk of building ahead of the flow.
    
        
    function placeAt(r, c){
  const cell = board[r][c];
  if (cell.kind === "source" || cell.filled) return;      // never these
  if (flowing && flow.r === r && flow.c === c) return;       // not the cell filling now
  if (cell.kind === "pipe") overwrites++;                  // replacing a pipe = overwrite
  const key = queue.shift();                               // take the next piece
  cell.kind = "pipe";
  cell.mask = PIECES[key];
  refill();                                                // top the queue back up
}

  5. 
        
    5
    The fuse, then release the water (fixed-timestep)
    
        
    A fuse counts down during the build phase; when it hits zero the water is released. To keep the flow ticking at the same rate on any monitor, bank the real elapsed time in an accumulator and spend it in fixed 1/120 s slices. Releasing sets a little walker at the source: its position, the side it entered from (none, for the source), and the side it will leave by.
    
        
    const STEP = 1/120, BUILD_TIME = 12, FLOW_INTERVAL = 0.9;
let last = performance.now(), acc = 0;
function frame(now){
  let dt = (now - last)/1000; last = now;
  if (dt > 0.25) dt = 0.25;                    // clamp a lag spike
  acc += dt;
  while (acc >= STEP){ update(STEP); acc -= STEP; }
  render(); requestAnimationFrame(frame);
}
function startFlow(){                            // fuse hit zero → release
  phase = "flow";
  flow = { r: source.r, c: source.c, from: 0, exit: source.dir, progress: 0, isSource: true };
}
    
      
    6. 

      
  6. 
        
    6
    A piece routes the water to its other opening
    
        
    This is the small heart of the flow. The water sits in a piece having entered through one side; the piece sends it out of its one other opening. Because a straight or an elbow has exactly two open sides, "the other opening" is just the mask with the entry bit cleared: mask & ~from. A cross is the one exception — it is a genuine crossover, so it sends the water straight through to the opposite side.
    
        
    function pieceExit(mask, from){
  if (mask === PIECES.CROSS) return OPP[from];   // crossover → straight through
  return mask & ~from;                            // the single OTHER open side
}
// examples:
//   elbow NE (N|E), water in from N → exit E
//   straight H (E|W), water in from W → exit E
//   cross,  water in from S → exit N  (straight across)
    
      
    7. 

      
  7. 
        
    7
    Connection matching — advance, or spring a leak
    
        
    Each flow tick fills the current piece a little; when it is full, the water tries to move on. It steps to the neighbour in its exit direction and asks one question: does that neighbour have the opposite opening facing back at me? That is the whole connectivity model — neighbour.mask & opposite(exit). If yes, the water advances and the distance climbs; if the neighbour is off the board, empty, or its openings do not line up, the flow has sprung a leak and stops dead.
    
        
    function stepFlow(dt){
  flow.progress += dt / FLOW_INTERVAL;
  while (flow.progress >= 1 && phase === "flow"){
    flow.progress -= 1;
    board[flow.r][flow.c].filled = true;                    // this piece is now full
    if (!flow.isSource) distance++;                         // count filled pipes
    if (distance >= GOAL) return win();                     // reached the goal!

    const [dr, dc] = DELTA[flow.exit];                      // step to the neighbour
    const nr = flow.r + dr, nc = flow.c + dc, entry = OPP[flow.exit];
    const nb = inBounds(nr, nc) ? board[nr][nc] : null;
    if (nb && nb.kind === "pipe" && (nb.mask & entry)){        // openings line up?
      flow = { r:nr, c:nc, from:entry, exit:pieceExit(nb.mask, entry), progress:flow.progress, isSource:false };
    } else {
      return lose();                                        // a leak — flow stops dead
    }
  }
}

  8. 
        
    8
    Win, lose, and wiring the tick
    
        
    The goal is a distance threshold: fill that many connected pipes and you win the instant the water reaches it. Spring a leak with fewer filled and you lose. The update tick is tiny — burn the fuse during the build phase, run the flow during the flow phase — and a click maps the pointer to a grid cell through the fixed 832×448 canvas so placement lands where you aim.
    
        
    const GOAL = 10;
function win(){ phase = "won";  showOver(true);  }
function lose(){ phase = "lost"; showOver(false); }

function update(dt){
  if (phase === "build"){
    buildTimer -= dt;
    if (buildTimer <= 0) startFlow();                       // fuse burned down
  } else if (phase === "flow"){
    stepFlow(dt);
  }
}
function onClick(e){                                        // client px → grid cell
  const b = canvas.getBoundingClientRect();
  const x = (e.clientX - b.left) * (canvas.width  / b.width);
  const y = (e.clientY - b.top ) * (canvas.height / b.height);
  const c = Math.floor((x - GX) / CELL), r = Math.floor((y - GY) / CELL);
  if (inBounds(r, c)) placeAt(r, c);
}
