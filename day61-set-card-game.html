A card here is one integer, 0 to 80, read as four base-3 digits: count, shape, shading, colour. The whole rulebook is then (a + b + c) % 3 === 0 on each digit — identical to "all same or all different", which the live check above demonstrates on every selection you make. Because the third card of any pair is forced, sets are not searched for but solved for, and the deck's 1080 sets and the 40-per-card figure are consequences, not trivia. 🔨 Build it yourself

    
SET is the rare game where choosing the right representation deletes almost all of the code. Refuse to model a card as an object of strings and model it as a four-digit number in base 3, and the rule collapses to a modular sum, the third card of a pair becomes a subtraction, and the board's whole analysis becomes a triple loop you can afford to run on every click. Nine blocks, in order, from an empty file — the deck, the rule, the completion, the enumerator, the deal loop, the feedback, the SVG, the cap set, and the loop that ties them together.

    1
    A card is a number in base 3, and the deck is every such number
    
        
    There are four attributes and each has three possible values, so a card is exactly a four-digit base-3 number and the deck is exactly the numbers 0 to 80. Do not store strings like "two red striped ovals" — store 34 and decode when you draw. Every good property of this codebase descends from this one decision, because arithmetic on digits is what the rule turns out to be.
    
        
    // digit 0 = count (1,2,3), 1 = shape, 2 = shading, 3 = colour
const attrsOf = id => [ ((id / 27) | 0) % 3, ((id / 9) | 0) % 3, ((id / 3) | 0) % 3, id % 3 ];
const idOf    = a  => a[0] * 27 + a[1] * 9 + a[2] * 3 + a[3];

const COUNT = ["1", "2", "3"];
const SHAPE = ["diamond", "squiggle", "oval"];
const SHADE = ["solid", "striped", "open"];
const COLOR = ["red", "green", "purple"];

const makeDeck = () => Array.from({ length: 81 }, (_, i) => i);   // 3^4 = 81, the whole deck

    The rule, written the way the rulebook says it
    
        
    Write the naive version first, because it is the one you can check against a human. For each attribute independently, the three values must be all equal or all distinct; a mix of two-and-one is what makes a triple fail. Note that the attributes never interact — the shapes do not care what the colours are doing — which is why the loop can bail out the moment any single attribute fails.
    
        
    function isSet(a, b, c){
  const A = attrsOf(a), B = attrsOf(b), C = attrsOf(c);
  for (let k = 0; k < 4; k++){
    const x = A[k], y = B[k], z = C[k];
    const allSame = (x === y && y === z);
    const allDiff = (x !== y && y !== z && x !== z);
    if (!allSame && !allDiff) return false;     // two-and-one: the only way to fail
  }
  return true;
}

    3
    The same rule as four modular additions
    
        
    Take three digits from {0,1,2}. If they are all equal the sum is 0, 3 or 6; if they are all distinct the sum is 0+1+2 = 3. Every other combination is a two-and-one and sums to 1, 2, 4 or 5. So "all same or all different" is exactly "sums to a multiple of 3" — one rule, not two, and no branches. Keep both functions in the file and assert they agree on all 85,320 triples; that test is the real proof, and it runs in milliseconds.
    
        
    function isSetMod3(a, b, c){
  const A = attrsOf(a), B = attrsOf(b), C = attrsOf(c);
  for (let k = 0; k < 4; k++)
    if ((A[k] + B[k] + C[k]) % 3 !== 0) return false;
  return true;
}

// sums of three digits from {0,1,2}
//   0+0+0=0  1+1+1=3  2+2+2=6      -> all same, all divisible by 3
//   0+1+2=3                        -> all different, divisible by 3
//   0+0+1=1  0+2+2=4  1+1+2=4 ...  -> two-and-one, never divisible by 3

    Two cards force the third — so solve, never search
    
        
    Rearrange the identity and the completion is free: if a + b + c ≡ 0 then c ≡ −a − b, computed digit by digit. Adding 6 before taking the remainder keeps JavaScript's % away from negative numbers. Two consequences follow immediately. Every pair of distinct cards belongs to exactly one set, so the deck holds C(81,2)/3 = 1080 of them; and given two cards, exactly one of the other 79 completes them, which is why beginners staring at two cards should be constructing the third rather than scanning.
    
        
    function thirdCard(a, b){
  const A = attrsOf(a), B = attrsOf(b), out = [0, 0, 0, 0];
  for (let k = 0; k < 4; k++) out[k] = (6 - A[k] - B[k]) % 3;   // c = -a - b (mod 3)
  return idOf(out);
}

// C(81,2) = 3240 pairs, each set counted 3 times  ->  3240 / 3 = 1080 sets
// a fixed card pairs with 80 others               ->  80 / 2   = 40 sets per card

    Enumerate all 220 triples, on every single click
    
        
    A twelve-card board has C(12,3) = 220 triples. That is nothing, so do not be clever: loop over all of them. One function then answers every question the interface has — how many sets are on the board, is there any set at all, and give me one to hint with. Being clever here (indexing by pairs, caching between deals) would buy microseconds and cost correctness bugs, and the "cheap enough to just do it" instinct is worth more than the micro-optimisation.
    
        
    function findSets(board){
  const out = [];
  for (let i = 0; i < board.length; i++)
    for (let j = i + 1; j < board.length; j++)
      for (let k = j + 1; k < board.length; k++)
        if (isSet(board[i], board[j], board[k])) out.push([i, j, k]);
  return out;                       // 220 triples on a 12-card board
}

const countSets = b => findSets(b).length;
const hasSet    = b => findSets(b).length > 0;

// the pair-first alternative, if you ever need it on a big board:
//   for each pair, compute thirdCard(a,b) and look it up  -> C(n,2) work instead of C(n,3)

    6
    Dealing: replace in place, and deal three more when the board is dead
    
        
    When a set is claimed, the three gaps are refilled from the deck in place so the rest of the board does not jump around under the player's eyes. If the deck is empty the board simply shrinks. Then comes the rule that surprises people: if the board contains no set at all, deal three more cards and check again. A random twelve-card board is set-free only about three per cent of the time, but it does happen, and the detector above is what makes handling it exact rather than a guess.
    
        
    function claim(state, idx){                    // idx = the three chosen positions
  idx.sort((p, q) => p - q);
  if (state.board.length > 12 || state.deck.length === 0){
    for (const p of idx.reverse()) state.board.splice(p, 1);   // shrink back toward 12
  } else {
    for (const p of idx) state.board[p] = state.deck.pop();    // refill in place
  }
  topUp(state);
}

function topUp(state){
  while (state.board.length < 12 && state.deck.length) state.board.push(state.deck.pop());
  while (!hasSet(state.board) && state.deck.length >= 3)      // the dead-board rule
    for (let i = 0; i < 3; i++) state.board.push(state.deck.pop());
}

    Say which attribute broke, not just "wrong"
    
        
    A red X teaches nothing. Because the four attributes are checked independently, the failing one is already known at the moment the test returns false — so return it instead of a bare boolean. Reporting "two of these are red and one is purple" turns a wrong guess into the exact lesson the player needed, and it costs four extra lines. This is the single highest-value thing in the whole file for a beginner.
    
        
    const ATTR_NAMES  = ["count", "shape", "shading", "colour"];
const ATTR_VALUES = [COUNT, SHAPE, SHADE, COLOR];

function brokenAttribute(a, b, c){
  const A = attrsOf(a), B = attrsOf(b), C = attrsOf(c);
  for (let k = 0; k < 4; k++){
    const x = A[k], y = B[k], z = C[k];
    if ((x === y && y === z) || (x !== y && y !== z && x !== z)) continue;
    return { index: k, name: ATTR_NAMES[k],
             values: [x, y, z].map(v => ATTR_VALUES[k][v]),
             sum: (x + y + z) % 3 };                 // never 0 when it breaks
  }
  return null;                                       // null = it really is a set
}

    The cap set, and measuring the odds instead of quoting them
    
        
    "How big can a set-free board be" is a real open research area — the cap set problem — and in four dimensions the answer is a settled 20. Hardcoding twenty card numbers proves nothing, so verify them in the browser: enumerate all 1,140 triples, then try adding each of the remaining 61 cards and confirm every one creates a set. The same honesty applies to the odds of a dead board: rather than repeating a number from a forum, deal thousands of random boards and measure it.
    
        
    const CAP20 = [0,1,3,4,9,10,12,13,27,28,32,35,38,47,59,65,66,67,71,77];

function verifyCap(board){
  let triples = 0, sets = 0;
  for (let i = 0; i < board.length; i++)
    for (let j = i + 1; j < board.length; j++)
      for (let k = j + 1; k < board.length; k++){ triples++; if (isSet(board[i],board[j],board[k])) sets++; }
  let outside = 0, forced = 0;                      // is it MAXIMAL?
  for (let c = 0; c < 81; c++){
    if (board.includes(c)) continue;
    outside++;
    if (hasSet(board.concat(c))) forced++;          // adding c always makes a set
  }
  return { triples, sets, outside, forced };        // 1140, 0, 61, 61
}

function measureDeadBoardOdds(trials){             // ~3% for 12 cards, measured not quoted
  let dead = 0;
  for (let t = 0; t < trials; t++) if (!hasSet(shuffle(makeDeck()).slice(0, 12))) dead++;
  return dead / trials;
}
