🔨 Build it yourself

    
A side-scroller looks like a lot of game but it is really just four small ideas stacked together: the world is a grid of characters, a fixed-timestep loop advances the physics in equal slices, the hero is a box with a velocity that gravity feeds every tick, and collision is resolved one axis at a time. Get that last one right — move horizontally then unstick, move vertically then land — and everything else (a following camera, coins, a stompable enemy, spikes, a goal flag) is a few lines each. Below is the whole engine in eight short blocks. Copy them in order.

    
    

      
  1. 
        
    1
    The world is a grid of characters
    
        
    There is no level editor and no data file — the entire level is an array of equal-length strings, one character per tile. # and = are solid, ^ is a spike, o a coin, E an enemy, G the goal and P the player's start. A single pass reads it into the things the game cares about: where the player spawns, where the coins and enemies are, and which cells are solid. A tile's pixel position is just its column and row times the tile size.
    
        
    const T = 32;                              // tile size in pixels
const LEVEL = [
  "                                     ",  // ... sky ...
  "        oo                       G   ",  // coins + goal flag
  "  #####    ##   ====   ^^   ###### ##",  // solid ground, platforms, spikes
  "  P    E        o          E         ",  // player start, enemies, a coin
];
const SOLID = new Set(["#", "="]);         // which glyphs you cannot pass through

function tileAt(c, r){                      // the glyph at column c, row r
  return (LEVEL[r] && LEVEL[r][c]) || " ";
}
function solid(c, r){
  if (c < 0) return true;                   // an invisible wall on the far left
  return SOLID.has(tileAt(c, r));           // off the top / bottom / right = empty
}

    The fixed-timestep loop
    
        
    If you advance the physics by however long the last frame took, the game behaves differently on a 60 Hz and a 144 Hz screen and a lag spike can teleport the player through a wall. The fix is an accumulator: bank the real elapsed time, then spend it in fixed 1/120 s chunks, calling update once per whole chunk. Rendering happens once per frame with whatever is left over. Now the simulation is deterministic and framerate-independent.
    
        
    const STEP = 1 / 120;                 // one physics slice = 1/120 of a second
let last = performance.now(), acc = 0;

function frame(now){
  let dt = (now - last) / 1000;       // real seconds since the last frame
  last = now;
  if (dt > 0.25) dt = 0.25;           // clamp after a tab-switch / lag spike
  acc += dt;                          // bank the time
  while (acc >= STEP){                 // spend it in equal fixed slices
    update(STEP);                     // physics always sees the SAME dt
    acc -= STEP;
  }
  render();                           // draw once per frame
  requestAnimationFrame(frame);
}
requestAnimationFrame(frame);

    3
    The hero is a box with a velocity, and gravity is one line
    
        
    The player is just a rectangle with a velocity (vx, vy). Horizontal input pushes the velocity toward a top speed with real acceleration, and when you let go, friction eases it back to zero so movement has weight. Gravity is the whole of the "falling" code: every tick it adds a constant to vy (capped so you never fall faster than one tile per step). Position then integrates from velocity — but only through the collision routine in the next step.
    
        
    const GRAVITY = 2200, MAXFALL = 1100;      // px/s^2 down, terminal speed
const MOVE = 210, ACCEL = 1600, FRICTION = 1400;

function movePlayer(dt){
  const dir = (keys.right ? 1 : 0) - (keys.left ? 1 : 0);
  if (dir !== 0){
    p.vx += dir * ACCEL * dt;              // accelerate toward top speed
    p.vx = clamp(p.vx, -MOVE, MOVE);
  } else {                                  // no input → friction to a stop
    const f = FRICTION * dt;
    p.vx = p.vx > 0 ? Math.max(0, p.vx - f) : Math.min(0, p.vx + f);
  }
  p.vy = Math.min(p.vy + GRAVITY * dt, MAXFALL);   // gravity — the whole of it
}

    4
    A jump with variable height, coyote-time and a buffer
    
        
    A good jump is three tiny rules. Variable height: starting the jump sets a big upward velocity; if you release the key while still rising, you cut that velocity in half, so a tap is a hop and a hold is a leap. Coyote-time: you may still jump for a few hundredths of a second after walking off a ledge, which forgives a late press. Jump-buffer: a press made a moment before landing is remembered and fires the instant you touch down.
    
        
    const JUMP = 680, COYOTE = 0.09, BUFFER = 0.10, CUT = 0.5;

function jumpLogic(dt){
  if (p.onGround) p.coyote = COYOTE; else p.coyote -= dt;   // grace after a ledge
  p.buf -= dt;
  if (pressedJump) p.buf = BUFFER;                          // remember an early press
  if (p.buf > 0 && p.coyote > 0){                            // fire when both are live
    p.vy = -JUMP; p.onGround = false; p.coyote = 0; p.buf = 0;
  }
  if (releasedJump && p.vy < 0) p.vy *= CUT;                // let go early → shorter jump
}

    5
    AABB tile collision — resolve one axis at a time
    
        
    This is the heart of the whole game. Never move both axes at once. First add vx to x, look at every solid tile the box now overlaps, and push the box back to that tile's edge — right side if you were moving right, left side if left — and zero vx. Then add vy to y and do it again vertically: landing snaps you to the tile top and marks you grounded; a rising hit snaps you under the tile. Splitting the axes turns a hard corner-case problem into two trivial 1-D ones and makes tunnelling impossible.
    
        
    function cells(o){                          // tile range the box overlaps
  return { c0: Math.floor(o.x / T),         c1: Math.floor((o.x + o.w - 0.01) / T),
           r0: Math.floor(o.y / T),         r1: Math.floor((o.y + o.h - 0.01) / T) };
}
function moveX(o){
  o.x += o.vx * STEP;                       // 1) move on X only
  const b = cells(o);
  for (let r = b.r0; r <= b.r1; r++) for (let c = b.c0; c <= b.c1; c++)
    if (solid(c, r)){                       // 2) unstick to the tile edge
      o.x = o.vx > 0 ? c * T - o.w : (c + 1) * T;
      o.vx = 0; return;                      //    and kill horizontal speed
    }
}
function moveY(o){
  o.y += o.vy * STEP;                       // 3) THEN move on Y only
  o.onGround = false;
  const b = cells(o);
  for (let r = b.r0; r <= b.r1; r++) for (let c = b.c0; c <= b.c1; c++)
    if (solid(c, r)){
      if (o.vy > 0){ o.y = r * T - o.h; o.onGround = true; }  // landed → stand
      else          o.y = (r + 1) * T;                        // bonked a ceiling
      o.vy = 0; return;                                        // landing zeroes fall
    }
}

    A camera that follows the player
    
        
    The level is far wider than the canvas, so instead of moving the world you move a camera: an (x, y) offset subtracted from everything when you draw. Centre it on the player, then clamp it to the level bounds so it never scrolls past the first or last column and shows empty space. That single clamp is what stops the classic "the camera ran off the edge of the map" bug.
    
        
    function updateCamera(){
  cam.x = clamp(p.x + p.w / 2 - VIEW_W / 2, 0, COLS * T - VIEW_W);
  cam.y = clamp(p.y + p.h / 2 - VIEW_H / 2, 0, ROWS * T - VIEW_H);
}
// when drawing anything:  screenX = worldX - cam.x;  screenY = worldY - cam.y;
function clamp(v, lo, hi){ return v < lo ? lo : v > hi ? hi : v; }

    7
    Enemies: patrol, then stomp or die
    
        
    An enemy is the same box-with-velocity as the player and reuses the exact same moveX/moveY collision. It patrols by walking one way until it hits a wall or runs out of floor ahead, then flips direction — so it never walks off its own platform. Against the player it is Mario's rule: if the player is falling and their feet are near the enemy's head, it is a stomp — the enemy dies and the player bounces; any other overlap is a side hit and costs a life.
    
        
    function updateEnemy(e, dt){
  e.vy = Math.min(e.vy + GRAVITY * dt, MAXFALL);
  moveX(e); if (e.hitWall) e.vx *= -1;          // bounce off walls
  moveY(e);
  if (e.onGround){                               // no floor ahead? turn around
    const ahead = e.vx > 0 ? e.x + e.w + 2 : e.x - 2;
    if (!solid(Math.floor(ahead / T), Math.floor((e.y + e.h + 2) / T))) e.vx *= -1;
  }
  if (overlap(p, e)){
    const stomp = p.vy > 0 && (p.y + p.h) - e.y < 16;   // falling onto its head
    if (stomp){ e.alive = false; p.vy = -520; }         // squash + bounce
    else       loseLife();                              // touched its side
  }
}

    Coins, spikes, pits, the flag — and the wiring
    
        
    The rest is a handful of overlap tests each tick. A coin box you overlap flips to collected. A spike tile under your box, or falling below the map (a pit), costs a life and respawns you at the start; lose all three and it is game over. Touch a G tile and you win. All of these run after the movement, once the player's final position for the tick is known.
    
        
    function update(dt){
  movePlayer(dt); jumpLogic(dt);
  moveX(p); moveY(p);                                   // resolve player collision
  enemies.forEach(e => e.alive && updateEnemy(e, dt));

  coins.forEach(c => { if (!c.got && overlap(p, c)) c.got = true; });
  if (spikeUnder(p) || p.y > ROWS * T + 80) loseLife(); // spike or bottomless pit
  if (goalUnder(p)) win();                              // reached the flag
  updateCamera();
}
function loseLife(){ if (--lives <= 0) gameOver(); else respawn(); }
